# Проверка конструктора параметров запуска

Дата: 2026-10-19. Ветка: `feat/launch-parameters-builder`.
Исходный коммит конструктора: `ed8a40f`; исходный коммит уточнений справки: `69dca24`. Версия результата: `0.8.0`.

## Реализованные сценарии

- Одна форма из разового запуска, дополнительных настроек базы и главного меню **Инструменты → Конструктор параметров запуска…**.
- Команды с собственными описаниями, категории, поиск, синтаксис, редакторы простых значений, выбор файла `/Out`, итоговая строка и явное копирование.
- Разовый результат возвращается в поле запуска; сохранённые параметры сначала возвращаются в дополнительные настройки, затем в редактор базы. Отмена внешнего редактора отменяет вложенный результат.
- Самостоятельный режим не требует выбранной базы, открывается с профилем старшей установленной платформы (без установок — 8.5.1), возвращаемый результат не сохраняет и не запускает 1С.
- 24 документальных профиля: 8.3.6–8.3.27, стабильная 8.5.1 и явно помеченная тестовая 8.5.4. Профилей 8.5.2/8.5.3 нет.

## Выполненные проверки

- Release-сборка MSVC, C++20, `/W4 /WX`; EXE — 2 057 728 байт (1,96 МиБ), версия ресурсов `0.8.0` / `0.8.0.0`, лимит поставки 8 МиБ соблюдён. По сравнению с исходным конструктором EXE вырос на 82 432 байт; сюда входят пояснения и изменения логики.
- Итоговый обычный прогон CTest: **5/5 PASS** — `ibstart.unit`, `ibstart.version_validation`, `ibstart.documentation_links`, `ibstart.launch_parameter_documentation`, `ibstart.parameter_dialog_contracts`.
- Новые проверки ядра: замена диапазона без перезаписи соседнего текста, неизвестные ключи, пробелы, кавычки, обратные слеши, пустой `/C`, неоднозначные фрагменты, повторения, конфликты, содержимое `/C`, похожее на режим или команду, границы версий и варианты значений.
- Нативные проверки вызывают реальные публичные API форм: неизменённая строка, отмена, закрытие крестиком, очистка, исправление незакрытой кавычки, переключение версии и темы, самостоятельный режим, возврат в разовый запуск, сохранение через два редактора и отмена внешнего редактора. Проверены заголовки столбцов, название формы и размещение элементов при уменьшении окна.
- Нативные автопроверки выполняются на отдельном рабочем столе тестового потока без переключения пользовательского рабочего стола. Они не запускают клиент 1С, не записывают пользовательские файлы и не изменяют буфер обмена.
- Матрица Markdown воспроизводится из проверенного каталога; `--check-docs` прошёл. Отдельно проверена сверка при CRLF в данных каталога, как после Windows checkout.
- Добавлены проверки выбора старшей установки с числовым сравнением, приоритета указанной версии, сохранения неизвестного профиля, истории наличия и встроенного текста для разных команд и версий. Проверено покрытие пояснениями всех 163 пунктов каталога во всех 24 профилях, отсутствие новых алгоритмов `/TComp` в старом профиле и правильное значение по умолчанию.
- Нативная проверка последовательно вводит `8.3.26` в дочерний EDIT списка: после каждого символа сохраняются текст и фокус. Проверка выявила автоматическое дополнение при повторной раскладке стандартного ComboBox; раскладка теперь сохраняет его текст и выделение. Проверен выбор старшей установленной версии при самостоятельном вызове.
- Справка компилируется в EXE. собственные пояснения хранятся в `parameter_help.inc`, значения — в `parameter_help.cpp`. Внешний файл справки не читается и не требуется.
- 163 собственных описания команд и 31 пояснение к значениям занимают 67 476 байт в UTF-16 с завершающими нулями, без таблиц и кода. Нативные проверки формы дополнительно выполнены из отдельной папки с одним тестовым EXE, без подпапки `reference` и файла справки: PASS. Проверены встроенные значения `/TComp` для старого и нового профиля, а также пояснение пакетной `/LoadCfg`.
- Уточнение подключения к хранилищу после `6fb4bdf`: поля F/N/P доступны в форме; проверены передача адреса с пробелами и учётных данных в команду DESIGNER, пустой пароль, пропущенное значение, повторный адрес, ограничение режима и маскирование пароля. Реальный вход в хранилище в этой проверке не выполнялся. Полный CTest после исправления: **5/5 PASS**.

## Наблюдавшаяся нестабильность существующих тестов

При первоначальных прогонах `TestUpdateTransportReadsAsyncResponse` периодически возвращал WinHTTP 12152. Локальная HTTP-фикстура отправляла ответ до чтения запроса. Исправлена только фикстура: перед отправкой ответа она ограниченно читает полные HTTP-заголовки. Код сетевого клиента приложения не менялся. После исправления HTTP-проверка прошла всю повторную серию.

В дополнительной серии из пяти повторов `ibstart.unit` первые четыре прогона прошли, а пятый упал в существующем `TestV8iConcurrentSavesConflict` на ожидании исходов конкурентных сохранений. Этот тест и механизм сохранения в данной доработке не менялись. Следующий полный обычный прогон прошёл 5/5. Таким образом, успешный итоговый CTest не объявляется доказательством стабильности этой отдельной гонки при многократных повторах.

В первом прогоне уточнений справки существующий `TestSafeStore` завершился ошибкой атомарной замены временного `ibases.v8i`: «Отказано в доступе». Код сохранения и этот тест в уточнениях не менялись. Следующий полный прогон прошёл 5/5; причина единичного отказа файловой системы не установлена.

## Границы доказательств

Последующая сверка вложенных параметров, расширение редактора и проверки
`/ConfigurationRepositoryCreate` / `/SetPredefinedDataUpdate` описаны
в [отдельном протоколе](verification-nested-launch-options.md).

Наличие команды и вариантов значений сверено по официальным разделам ИТС. Это не подтверждение исполнения на 24 установленных версиях платформы. Неизвестное семейство не наследует соседнюю версию. Отсутствие определения в справочнике не доказывает невозможность исполнения на платформе.

Структурированные редакторы реализованы для части обычных команд. Сложные вложенные, пакетные, web/mobile, создание базы, агент и OLE остаются справочными; их полная грамматика не считается реализованной. Неизвестные или неоднозначные фрагменты сохраняются для ручной правки.

Форма конструктора просмотрена на рабочем столе при масштабе 100%; поведение окончательных вариантов вызова проверено нативными тестами. Отдельная визуальная приёмка всех масштабов Windows не проводилась. Буфер обмена проверялся по общей реализации копирования и наличию команды; автотесты намеренно не перезаписывают пользовательский буфер.
