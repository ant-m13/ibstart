# Оформление встроенной справки конструктора

Дата: 2026-10-20. Ветка: `feat/launch-parameters-builder`.

## Поведение

Описание использует штатный Unicode Rich Edit из системной `Msftedit.dll`.
Имена команд выделены жирным; вложенные опции, обозначения `<аргумент>`
и имена полей в маркированных разделах — цветом. Основной текст остаётся
обычным. Поле доступно с клавиатуры, допускает выделение и копирование,
сохраняет переносы строк, прокрутку и режим только для чтения.

На светлом фоне используется `#A02020`, на тёмном — `#FF9090`. При включённой
высокой контрастности собственный цвет заменяется системным цветом текста,
а параметры дополнительно выделяются жирным. Изменение системных цветов
и DPI обновляет оформление; выделение, прокрутка и фокус при перекрашивании
сохраняются. Настройки высокой контрастности на компьютере пользователя
во время проверки не переключались.

Форматирование применяется к обычному тексту сообщений; HTML/RTF из
справочников не загружается. Для диапазонов используется `GT_RAWTEXT`:
индексы символов совпадают с внутренним представлением Rich Edit, где
перевод абзаца занимает один CR. Это исключает смещение после кириллицы
и нескольких абзацев. При недоступности системного компонента остаётся
обычное поле текста. Документация API:
[форматирование](https://learn.microsoft.com/en-us/windows/win32/controls/format-text-in-rich-edit-controls),
[GETTEXTEX](https://learn.microsoft.com/en-us/windows/win32/api/richedit/ns-richedit-gettextex).

## Прокрутка к заголовку выбранного параметра

Последующая доработка 2026-10-20, базовый коммит `73101d9`.
После замены EDIT на Rich Edit переход к параметру всё ещё рассчитывался
по исходным CRLF-смещениям. На длинном описании `/LoadConfigFromFiles`
заголовок `• -NoCheck` оказывался выше видимой области.

Поиск якоря теперь использует текст самого поля (`GT_RAWTEXT` для Rich Edit),
полную строку заголовка с синтаксисом опции и границей абзаца. Номер строки
получается через `EM_EXLINEFROMCHAR`; для резервного обычного EDIT сохраняется
его собственное представление текста и `EM_LINEFROMCHAR`. Чтение текста
для оформления и прокрутки использует общий метод.

Регрессионная проверка настоящей формы сначала воспроизвела скрытый заголовок
на прежнем коде, затем прошла после исправления. По координатам символов
проверены начало и конец заголовка и начало описания внутри поля:
`-NoCheck`, `-updateConfigDumpInfo`, повторный выбор `-NoCheck`, а также
перенос длинного `-ConfigurationExtensionsLogIntegrity`. Для последнего
проверка временно увеличивает шрифт только тестового поля; системные настройки
не меняются. Снимки до/после и снимок перенесённого заголовка просмотрены
визуально; они находятся в `out/ui-parameter-builder/scroll-heading-before/`
и `out/ui-parameter-builder/scroll-heading-after/`.

После исправления: Release MSVC `/W4 /WX` — PASS, CTest — 5/5 PASS,
строгая сборка сайта и `git diff --check` — PASS. Обновлённый основной
EXE занимает 2 432 000 байт.
