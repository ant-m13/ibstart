# Проверка обновлений при запуске

Дата: 2026-10-21. Базовый commit: `e626f80`, ветка `feat/configuration-catalog`.
Версия приложения остаётся `0.8.0`.

## Поведение

- **Настройки → Параметры приложения… → Запуск → Проверять обновления при запуске программы**.
  По умолчанию включено, в том числе при чтении старого профиля без нового поля.
- `settings.json` хранит `check_updates_on_startup` как `0`/`1`; значение переносится
  при импорте/экспорте и участвует в объединении изменений устаревших снимков настроек.
- При `0` запуск приложения не вызывает проверку и сетевой запрос. Ручная команда
  **Справка → Проверить обновления…** доступна независимо от настройки.
- При `1` одна проверка начинается после показа окна. Нет таймера повторных запросов;
  изменение настройки применяется со следующего запуска. Возврат к работающему окну
  и переключение режима не запускают новую проверку.
- Стартовая проверка не открывает диалоги. Более новый релиз добавляет команду
  **Доступно обновление …** после **Справка** либо после **Режим** в простом режиме.
  Команда открывает страницу найденного релиза. Ручная проверка сохраняет подробные
  диалоги результата и ошибки.
- Индикатор сохраняется при перестроении меню и открытии страницы; успешная проверка,
  не находящая более новой версии, очищает его. Ошибка не стирает ранее найденный релиз.
  Между запусками результат не сохраняется. Ошибки стартовой проверки пишутся в журнал.
- Используются существующие транспорт, SemVer-сравнение и отмена фоновой операции.
  Закрытие окна отменяет незавершённую проверку. Файлы приложения не загружаются
  и не заменяются автоматически.

  отмена при закрытии, ручная команда при `0`, запрет дублирующего запроса и сохранение

- `git diff --check`: PASS.

В отдельном прогоне, пересекавшемся с другими проверками, существующий
`ibstart.parameter_dialog_contracts` достиг лимита 60 с. В итоговом последовательном
наборе он прошёл за 38,22 с; лимит теста и его сценарии не менялись. Итоговый результат
7/7 относится к полному последнему прогону, а не к объединению выборочных запусков.

Тест обновлений подменяет только сетевую границу `FetchLatestVersionAsset` при линковке
тестового EXE. Фоновый поток, разбор версии, сравнение, сообщения окна, обработчики
команд, форма настроек и native menu выполняются кодом приложения. Пользовательский
профиль и реальные базы не используются; обращения к GitHub из этого теста нет.
Тестовый рабочий стол имеет разрешение `DESKTOP_CREATEMENU`; без него Windows
не создаёт меню и такой прогон не доказывает поведение главного меню.

## Осмотр интерфейса и границы доказательств

Снимки настоящих окон сохранены и просмотрены:

- `out/startup-update-evidence/update-settings.bmp` — вкладка «Запуск» с включённой
  галочкой и заголовком окна. Элементы не пересекаются, кнопки ОК/Отмена доступны.
- `out/startup-update-evidence/update-main.bmp` — индикатор после «Справка».
- `out/startup-update-evidence/update-simple.bmp` — тот же индикатор после «Режим».

Номер `99999.0.0` на снимках — синтетический ответ тестового транспорта, а не опубликованный
релиз. Проверка не подтверждает реальное соединение с GitHub, открытие браузера по клику,
полную матрицу DPI/Windows или публикацию новой версии. Исправлена обработка
`WM_NCCREATE` формы настроек: `DefWindowProcW` сохраняет стандартный заголовок окна;
заголовок дополнительно проверяется автоматическим сценарием.

Push, merge и публикация релиза в рамках доработки не выполнялись.
