# Проверка и подготовка IBStart 0.8.0

Дата: 2026-10-21. Релизная ветка: `codex/release-0.8.0`.
Протокол относится к локальной подготовке выпуска. GitHub Release не опубликован.

## Состав релиза

Релизная ветка создана от актуальной `origin/main` (`4cc02b7`). После обновления
сведений с сервера обнаружена переписанная история `main`. Доработки перенесены
по разнице содержимого относительно прежней базы `fe08c47`, без слияния старой
истории. Исходные ветки сохранены.

| Исходная ветка | Проверенный конец ветки | Результат включения |
| --- | --- | --- |
| `feat/github-pages` | `2cc0e3c` | Соответствующие изменения уже есть в актуальной `main`; повторное включение не требуется |
| `feat/launch-parameters-builder` | `847734a` | Конструктор, встроенная справка, грамматика, матрицы версий и документация включены |
| `feat/configuration-catalog` | `ecb5415` | Включает ветку конструктора, справочник конфигураций, версии баз, отдельные редакторы, стартовую проверку обновлений и значки меню |

Сохранена политика публикации актуальной `main`. Конфликты трёх справочных
страниц разрешены с сохранением новых матриц и ссылок. Изменения из старых веток
не объявляются результатами проверки на реальных базах 1С.

## Найденные и исправленные ошибки

- Поиск `/AppArch` ошибочно рассматривал значения в кавычках как команды.
  Например, `/N "/AppArch"` приводил к ошибке отсутствующего значения разрядности.
  Теперь такие значения пропускаются; настоящий следующий `/AppArch x86_64`
  по-прежнему учитывается. Проверены имя пользователя, пароль, выходной файл
  и пароль хранилища. Новый регрессионный сценарий сначала воспроизвёл сбой
  `AppArch parameter has no value`, затем прошёл после исправления.
- Главная страница и инструкция выпуска описывали только ручную проверку
  обновлений. Теперь описаны оба способа, настройка отключения и отсутствие
  автоматической установки. Добавлен снимок актуальной вкладки «Запуск».
- Обновлены сведения о версии в политике безопасности, статус будущих этапов,
  описание справочных данных и собственных стилей сайта, инструкции участникам.
- Проверки воспроизводимости справочных данных и Python-тесты добавлены в
  `build.yml` и `release.yml`. Проверка Pages запускается также при изменении
  инструментов и ядра конструктора. Демонстрационный профиль для снимков
  создаётся с отключённой сетевой проверкой обновлений.

и рабочие базы не используются.

проверкой `ibstart_update_ui_tests --capture`. Проверены заголовок, доступность
галочки обновлений и кнопок, отсутствие пересечений в показанном масштабе.
Тестовый ответ `99999.0.0` не используется в пользовательских снимках документации.

## Границы и публикация

- Автоматическое определение конфигурации и версии из базы и проверка актуальных
  релизов конфигураций 1С не реализованы. Версия базы вводится вручную.
- Локальные тесты не подтверждают выполнение всех команд в каждой версии 1С,
  реальные учётные данные, соединение с рабочими базами, полную матрицу Windows,
  DPI и высокой контрастности. Сохранённые протоколы отдельных доработок остаются
  историческими свидетельствами со своими датами и границами.
- Проверка с подменённым транспортом не доказывает реальный HTTP-запрос к GitHub.
  Наличие опубликованного `v0.7.8` проверено отдельно через GitHub; тег `v0.8.0`
  на момент подготовки свободен.
- Удалённые CI/CodeQL, merge, создание тега, публикация Release и развёртывание
  Pages выполняются после отправки и принятия PR по [процессу выпуска](release-process.md).
  Локальная подготовка не выполняет эти действия.

Локальные артефакты предназначены для просмотра перед публикацией и находятся
в исключённом из Git каталоге `out/release-0.8.0/`. Автоматический выпуск после
merge повторно собирает EXE на точном коммите `main` и формирует свои контрольные суммы.
