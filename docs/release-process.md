# Выпуск IBStart

Релиз создаётся автоматически после принятия pull request в `main`. Прямой ручной выпуск по тегу не требуется.

## Подготовка pull request

1. Измените единственный источник версии в `cmake/IBStartVersion.cmake`. Используйте SemVer без build metadata, например `0.7.2` или `1.0.0`.
2. Добавьте в `CHANGELOG.md` раздел с тем же номером и описанием пользовательских изменений.
3. Локально выполните Release-сборку и тесты:

   ```powershell
   cmake --preset msvc-x64-release
   cmake --build --preset msvc-x64-release
   ctest --preset msvc-x64-release
   ```

4. Создайте pull request в `main`. Workflow `build.yml` проверит формат версии, отсутствие соответствующего тега `v<версия>`, версию внутри `IBStart.exe`, CTest и предел размера 8 МиБ. Отдельный `codeql.yml` выполнит статический анализ C++ на фактической MSVC/CMake-сборке; его результаты доступны в GitHub Code Scanning.

## Автоматический выпуск после merge

После принятия PR workflow `release.yml` работает с точным коммитом, появившимся в `main`, и последовательно:

1. через GitHub API подтверждает, что коммит появился в `main` после принятия PR (прямой push не выпускается);
2. повторно собирает Release и запускает CTest;
3. проверяет `ProductVersion` готового `IBStart.exe`;
4. создаёт portable ZIP с пустым маркером `IBStart.portable`, SHA-256 `checksums.txt` и release asset `IBStart.version` с SemVer-версией;
5. создаёт аннотированный тег `v<версия>` на этом коммите;
6. публикует стабильный GitHub Release `IBStart <версия>` с заметками текущей версии, EXE, portable ZIP, `checksums.txt` и `IBStart.version`.

Повторный запуск workflow безопасен: существующий тег принимается только тогда, когда он указывает на тот же коммит, а assets релиза обновляются через `--clobber`. Если версия уже относится к другому коммиту, выпуск останавливается — необходимо создать новый PR с увеличенным номером.

Нельзя добавлять упаковщики EXE, автообновление, телеметрию или секреты в артефакты. Разрешена только ручная проверка версии с переходом на GitHub Release: она не должна скачивать или заменять EXE. Перед merge вручную проверьте приложение на поддерживаемой Windows и убедитесь, что в логах нет пароля, токена либо строк `/P` с исходным значением.

Если pull request меняет `.github/workflows/release.yml`, после merge отдельно проконтролируйте запуск release workflow. Для публикации у него уже задано минимально необходимое разрешение `contents: write`.
