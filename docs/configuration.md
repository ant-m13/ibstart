# Конфигурация, локальные данные и файлы IBStart

Этот справочник описывает форматы и расположение файлов, которые использует IBStart версии `0.7.4`. Он предназначен для пользователей, администраторов и сопровождающих. Основной способ изменения настроек — интерфейс приложения: ручное редактирование необходимо только для диагностики, переноса профиля или автоматизации.

Все текстовые файлы, создаваемые IBStart, записываются в UTF-8. Перед ручным изменением закройте приложение и сделайте копию файла. `settings.json` и `catalog-state.json` сохраняются атомарной заменой, однако собственные резервные копии для них приложение не создаёт.

## Карта файлов

| Файл или каталог | Обычный режим | Portable mode | Назначение |
| --- | --- | --- | --- |
| `settings.json` | `%LOCALAPPDATA%\IBStart\settings.json` | `<папка EXE>\data\settings.json` | Настройки окна, списка, отображения и поиска платформ. |
| `catalog-state.json` | `%LOCALAPPDATA%\IBStart\catalog-state.json` | `<папка EXE>\data\catalog-state.json` | Избранное, недавние запуски, теги, стили тегов и время запусков. |
| `logs\` | `%LOCALAPPDATA%\IBStart\logs\` | `<папка EXE>\data\logs\` | Журналы работы приложения. Это не конфигурация. |
| `IBStart.portable` | рядом с `IBStart.exe`, если режим включён вручную | уже находится в portable ZIP рядом с `IBStart.exe` | Пустой маркер, который включает portable mode. |
| `ibases.v8i` | выбранный пользователем внешний путь | тот же выбранный пользователем внешний путь | Список групп и баз 1С. Не копируется в папку данных IBStart. |
| `ibases.v8i.bak_…` | рядом с выбранным `ibases.v8i` | рядом с выбранным `ibases.v8i` | До пяти последних резервных копий списка баз. |

Если `IBStart.portable` отсутствует, имеет ненулевой размер или не является обычным файлом, используется обычный режим. Чтобы перенести профиль между двумя копиями приложения, скопируйте `settings.json` и `catalog-state.json` при закрытом IBStart; журналы при необходимости можно не переносить.

Portable mode переносит только собственные данные IBStart. Кэши, профили и иные данные платформы 1С продолжают размещаться в её каталогах Windows, например `%APPDATA%\1C\1Cv8` и `%LOCALAPPDATA%\1C\1Cv8`.

## `settings.json` — настройки приложения

Файл создаётся после первого сохранения настройки или закрытия окна. Отсутствующий файл означает значения по умолчанию. Пример полного файла:

```json
{
  "active_ibases": "C:\\Users\\Anton\\AppData\\Roaming\\1C\\1CEStart\\ibases.v8i",
  "selected_entry": "Бухгалтерия",
  "simple_mode": 0,
  "show_tags_in_list": 1,
  "folders_first_when_sorting": 1,
  "window_x": 120,
  "window_y": 80,
  "window_width": 1180,
  "window_height": 720,
  "recent_lists": [
    { "recent_list": "D:\\1C\\team-ibases.v8i" }
  ],
  "platform_paths": [
    { "platform_path": "D:\\1C-platforms" }
  ]
}
```

| Параметр | Тип и значение по умолчанию | Описание |
| --- | --- | --- |
| `active_ibases` | строка, по умолчанию пустая | Полный путь к активному `ibases.v8i`. Если значение пусто, IBStart ищет стандартный список 1С. |
| `selected_entry` | строка, по умолчанию пустая | Имя последней выбранной базы или группы; после открытия списка приложение пытается восстановить выделение. |
| `simple_mode` | целое `0`/`1`, по умолчанию `0` | Компактный простой режим. Любое ненулевое целое воспринимается как включённое значение. |
| `show_tags_in_list` | целое `0`/`1`, по умолчанию `1` | Показывать цветные теги рядом с базами в дереве. В простом режиме они не рисуются. |
| `folders_first_when_sorting` | целое `0`/`1`, по умолчанию `1` | При сортировке по имени располагать группы выше баз. Значение действует при следующей команде сортировки. |
| `window_x`, `window_y` | целые, по умолчанию системное размещение | Координаты обычного окна в физических пикселях. Если сохранённый прямоугольник не попадает ни на один монитор, IBStart использует системное размещение. |
| `window_width` | целое, по умолчанию `900` | Сохранённая ширина окна. При чтении ограничивается диапазоном `480…10000`, затем при запуске дополнительно применяется минимальная ширина интерфейса. |
| `window_height` | целое, по умолчанию `560` | Сохранённая высота окна. При чтении ограничивается диапазоном `320…10000`, затем при запуске применяется минимальная высота интерфейса. |
| `recent_lists` | массив объектов | Недавно открытые списки баз. Каждый объект содержит строку `recent_list` с полным путём. Через интерфейс сохраняется не более девяти путей; недоступный путь удаляется при попытке открытия. |
| `platform_paths` | массив объектов | Дополнительные корни поиска платформы 1С. Каждый объект содержит строку `platform_path`. Внутри корня IBStart ищет `1cv8.exe` и `1cv8c.exe` (в том числе в `bin\`) на нескольких уровнях вложенности. |

Стандартный поиск `ibases.v8i` выполняется в `%APPDATA%\1C\1CEStart\ibases.v8i`, `%APPDATA%\1C\1Cv8\ibases.v8i` и `%LOCALAPPDATA%\1C\1CEStart\ibases.v8i`.

Для настроек с логическим смыслом записывайте именно `0` или `1`, а не JSON-литералы `true` и `false`: текущий формат хранит эти значения как числа. Отсутствующее или неверного типа свойство игнорируется, а остальные корректные свойства продолжают использоваться. Если повреждён весь JSON-файл, применяются настройки по умолчанию. Неизвестные свойства не являются расширяемым API и могут исчезнуть после следующего сохранения файла.

## `catalog-state.json` — метаданные каталога и теги

Этот файл не изменяет `ibases.v8i` и относится к конкретному локальному профилю IBStart. Он связывает теги и историю с базами выбранного списка. Полный пример:

```json
{
  "schema_version": 1,
  "favorites": [
    { "favorite": "Бухгалтерия" }
  ],
  "history": [
    { "history_id": "{11111111-1111-4111-8111-111111111111}", "time": 1787560200, "mode": 0 }
  ],
  "last_launches": [
    { "last_launch_id": "{11111111-1111-4111-8111-111111111111}", "time": 1787560200 }
  ],
  "tags": [
    {
      "tag_id": "{11111111-1111-4111-8111-111111111111}",
      "values": ["Продуктив", "Клиент А"]
    }
  ],
  "tag_styles": [
    { "tag_style": "Продуктив", "background": 16054978, "text": 5636096 }
  ]
}
```

| Параметр | Тип | Описание |
| --- | --- | --- |
| `schema_version` | целое | Записываемая версия структуры. Текущая версия — `1`. Сейчас приложение записывает это поле как информацию о формате; отдельного поведения для других версий схемы пока нет. |
| `favorites` | массив объектов `{ "favorite": "имя" }` | Избранные базы по имени раздела в `ibases.v8i`. Интерфейс хранит максимум девять записей и при переименовании базы обновляет имя. Несуществующие имена не отображаются. |
| `history` | массив объектов | Последние двадцать запусков. Поля: `history_id` — идентификатор базы, `time` — число секунд Unix epoch, `mode` — `0` для «Предприятия», `1` для «Конфигуратора», `2` для web client. Новый запуск той же базы переносится в начало списка. |
| `last_launches` | массив объектов | Время последнего запуска для сортировки по запуску. Поля: `last_launch_id` и `time` в секундах Unix epoch. Очистка раздела «Недавние» удаляет `history`, но намеренно не удаляет эти значения, чтобы не менять сортировку. |
| `tags` | массив объектов | Назначения тегов. `tag_id` — идентификатор базы, `values` — непустой массив строковых названий тегов. |
| `tag_styles` | массив объектов | Оформление отдельных тегов. `tag_style` — название тега, `background` и `text` — целые значения `COLORREF` от `0` до `16777215`. |

Для `tags`, `history` и `last_launches` идентификатор базы — значение поля `ID` в её секции `ibases.v8i`; если поля `ID` нет, используется имя базы. Поэтому для устойчивого переноса тегов и истории между переименованиями рекомендуется уникальный непустой `ID`. При изменении ID вручную теги и история не мигрируют автоматически.

Названия тегов в интерфейсе сравниваются без учёта регистра. Цвет удобнее задавать через **Вид → Настроить теги…**, где применяется привычная запись `#RRGGBB`. В файле сохраняется не строка `#RRGGBB`, а десятичный Windows `COLORREF` с внутренним порядком байтов `0x00BBGGRR`; вручную изменять эти числа следует только при понимании этого формата.

Неверно сформированный элемент массива пропускается без сброса остальных корректных записей. Если повреждён весь JSON-файл, каталог открывается без локальных метаданных. Неизвестные корневые свойства и поля внутри объектов не сохраняются как расширение формата: после следующей записи приложение создаст каноническую структуру, показанную выше.

## `ibases.v8i` — список информационных баз 1С

`ibases.v8i` — внешний список, совместимый со стартером 1С. IBStart читает UTF-8 с BOM или без BOM, сохраняет исходный тип перевода строк и порядок известных и неизвестных строк. Секция с полем `Connect` считается базой; секция без `Connect` считается группой.

Полный аудит совместимости с актуальным снимком документации 1С:Предприятие
8.5.1, реестр всех обнаруженных полей и параметров запуска, ограничения
текущей реализации и план дальнейшей разработки находятся в
[спецификации ibases и запуска 1С](ibases-launch-spec.md). Таблицы ниже
описывают фактическое поведение текущей версии IBStart, а не обещают поддержку
всех перечисленных в спецификации возможностей.
Правила того, какие материалы 1С можно использовать в репозитории и выпускных
архивах, собраны в [политике лицензирования материалов 1С:ИТС](1c-license-compliance.md).

Описание структуры и полей вынесено в [спецификацию формата `ibases.v8i`](ibases-format.md),
а полный реестр команд и параметров — в [спецификацию запуска 1С](launch-parameters.md).

```ini
[Файловые базы]
Folder=/
OrderInList=1
OrderInTree=1

[Бухгалтерия]
Connect=File="D:\1C\Бухгалтерия"
ID={11111111-1111-4111-8111-111111111111}
Folder=/Файловые базы
OrderInList=1
OrderInTree=1
Version=8.3.27
App=ThinClient
WA=1
ClientConnectionSpeed=Normal
AppArch=x86_64_prt
AdditionalParameters=/N "Иван"
```

### Структура секций и расположение

| Поле | Применяется к | Допустимые значения и поведение |
| --- | --- | --- |
| `[Имя]` | база или группа | Имя секции должно быть уникальным без учёта регистра. Оно используется в дереве и для избранного. |
| `Connect` | база | Строка подключения. Наличие поля отличает базу от группы. Поддерживаются `File="путь"`, `Srvr="кластер";Ref="имя"`, `WS="http(s)://адрес"` и legacy-вариант, где первый фрагмент — прямой `http(s)://` URL. Дополнительные фрагменты подключения сохраняются при редактировании. |
| `ID` | база | Стабильный уникальный идентификатор. При добавлении базы IBStart создаёт GUID. Используется для тегов, истории и сортировки по последнему запуску; не делайте его пустым и не назначайте один ID нескольким базам. |
| `Folder` | база или группа | Абсолютный путь группы в формате 1С: `/` — корень, `/Группа/Подгруппа` — вложенная группа. IBStart обновляет путь при перетаскивании, перемещении и переименовании групп. |
| `OrderInList` | база или группа | Неотрицательное целое — порядок среди соседних записей. При ручном перемещении и сохранённой сортировке IBStart перенумеровывает прямых потомков. |
| `OrderInTree` | база или группа | Неотрицательное целое — приоритет порядка в дереве. Если оно отсутствует, используется `OrderInList`. При изменении порядка через интерфейс оба поля синхронизируются. |

Нормальный путь к файловой базе в `Connect` указывает на каталог, содержащий `1Cv8.1CD`. При добавлении файловой базы IBStart требует существующий `1Cv8.1CD`; при уже существующем подключении файл не удаляется и не изменяется. Для серверной базы нужны оба ключа `Srvr` и `Ref`. Веб-база запускается только в режиме «Предприятие» и только тонким клиентом `1cv8c.exe`; «Конфигуратор» для неё недоступен.

### Параметры запуска базы

| Поле | Значения | Как использует IBStart |
| --- | --- | --- |
| `Version` | версия платформы или пусто | Предпочтительная версия для запуска. Допускается начало версии, например `8.3.27` сопоставляется с установленной `8.3.27.1688`. Пустое значение означает «Авто». |
| `DefaultVersion` | версия или пусто | Используется, только когда `Version` пусто. |
| `App` | `Auto`, `ThickClient`, `ThinClient`, `WebClient` | Режим клиента. `Auto` или пустое значение разрешает выбор по умолчанию. `ThinClient` требует наличия `1cv8c.exe`, а `WebClient` допустим только для веб-базы. Для веб-базы IBStart всегда пытается выбрать тонкий клиент: сначала ищет версию из `Version`/`DefaultVersion`, а при её отсутствии — самую новую совместимую установку. Если подходящей установки нет из-за отсутствия клиента, версии, разрядности или архитектуры, браузер открывается как fallback. |
| `DefaultApp` | обычно `ThickClient`, `ThinClient` или пусто | Предпочтение при автоматическом выборе, если `App` пусто или `Auto`. |
| `WA` | обычно `1` или `0` | Аутентификация ОС. `0`, `false` и `no` выключают флаг; любое другое непустое значение включает его. Значение совместимо сохраняется в списке 1С. |
| `External` | обычно `1` или `0` | Признак внешней записи общего списка. Не меняет логику запуска IBStart; обычно задаётся источником общего списка. |
| `Locale` | например `ru_RU` или пусто | Локаль запуска 1С. Пустое поле оставляет стандартное поведение платформы. |
| `ClientConnectionSpeed` | `Normal` или `Low` | Предпочитаемая скорость соединения, сохраняемая в формате 1С. |
| `AppArch` | `x86`, `x86_64`, `x86_prt`, `x86_64_prt` или пусто | Выбор разрядности: только 32-bit, только 64-bit, приоритет 32-bit, приоритет 64-bit либо автоматический выбор. |
| `AdditionalParameters` | строка аргументов 1С | Дополнительные аргументы запуска. Ключ `/AppArch` или `/AppArch=<значение>` имеет приоритет над `AppArch`. Не храните здесь `/P`, пароли, токены и другие секреты. |

Остальные поля `ibases.v8i` не удаляются намеренно. IBStart сохраняет незнакомые ключи и строки в исходном порядке; это важно для совместимости со стандартным стартером 1С и сторонними инструментами. Однако стороннее поле не становится настройкой IBStart, пока приложение не начнёт явно его поддерживать.

Перед сохранением выбранного списка IBStart проверяет, не изменился ли файл другой программой, создаёт копию `ibases.v8i.bak_ГГГГММДД_ЧЧММСС` рядом с ним и выполняет атомарную замену. Хранится до пяти последних резервных копий. При конфликте перезагрузите список вместо принудительной перезаписи.

## Маркер `IBStart.portable`

Это пустой файл-маркер `IBStart.portable`, расположенный в той же папке, что и `IBStart.exe`. Его содержимое должно быть пустым, размер — ровно `0` байт.

```text
IBStart.exe
IBStart.portable    ← пустой файл
data\
```

Наличие именно пустого файла меняет корень локальных данных на `data\`. Portable-архив из GitHub Release уже содержит этот маркер. Отдельно скачанный EXE работает в обычном режиме, пока пользователь не создаст такой файл самостоятельно.

## Журналы, кэш и служебные файлы

`logs\ibstart_ГГГГММДД_ЧЧММСС.log` создаётся для каждого запуска. IBStart хранит до десяти файлов с расширением `.log` в каталоге журналов. Перед записью маскируются значения после `/P`, `password`, `token` и `secret`, а также полностью скрывается операнд после `/IBConnection`; журнал не является безопасным хранилищем секретов.

Команда очистки кэша не использует путь из `Connect` и никогда не удаляет каталог файловой базы. Она рассматривает только подкаталоги с идентификатором базы в:

```text
%APPDATA%\1C\1Cv8\<ID>
%LOCALAPPDATA%\1C\1Cv8\<ID>
%LOCALAPPDATA%\IBStart\cache\<ID>
```

Каталоги `licenses`, `license` и `lic` исключены. Эти кэши не являются настройками IBStart и не переносятся portable mode.

## Конфигурация сборки и выпуска

Эти файлы предназначены для разработчиков, а не для установки приложения пользователем.

| Файл | Параметры и назначение |
| --- | --- |
| `cmake/IBStartVersion.cmake` | Единственный источник номера версии. `IBSTART_VERSION` — SemVer без build metadata; `IBSTART_GITHUB_OWNER` и `IBSTART_GITHUB_REPOSITORY` определяют репозиторий для ручной проверки обновлений и страницы релиза. |
| `CMakePresets.json` | Два Release-пресета с `BUILD_TESTING=ON`: `msvc-x64-release` для Ninja в `out/build/msvc-x64-release` и `vs2022-x64-release` для Visual Studio 2022 в `out/build/vs2022-x64-release`. |
| `.github/workflows/build.yml` | Проверяет версию и соответствующий раздел changelog, собирает Release, запускает CTest, проверяет размер EXE (не более 8 МиБ), создаёт portable ZIP и проверяет маркер внутри него. |
| `.github/workflows/codeql.yml` | Анализирует C++-код CodeQL при pull request в `main`, изменениях `main`, раз в неделю и вручную. Для корректного анализа запускает фактическую MSVC/CMake-сборку; результаты доступны в GitHub Code Scanning. |
| `.github/workflows/release.yml` | После merge PR в `main` повторно собирает выпуск, создаёт тег, GitHub Release, EXE, portable ZIP, `checksums.txt` и `IBStart.version`. Подробный процесс описан в [release-process.md](release-process.md). |

`IBStart.version` — не конфигурация пользователя, а release asset с единственной SemVer-строкой и переводом строки. Приложение получает его только по явной команде **Справка → Проверить обновления…**. `checksums.txt` содержит SHA-256 для `IBStart.exe` и portable ZIP; используйте его для проверки скачанных файлов.

## Рекомендации по ручному изменению

1. Закройте все экземпляры IBStart.
2. Скопируйте изменяемый JSON или `ibases.v8i` в резервную папку.
3. Сохраняйте JSON в UTF-8 и не меняйте типы полей: строки остаются строками, числа — числами, массивы объектов — массивами.
4. Не удаляйте `ID` у баз с тегами или историей и не копируйте один ID между разными базами.
5. После изменения запустите IBStart и убедитесь, что список, теги и настройки отображаются ожидаемо. При ошибке верните резервную копию.

Для идей, которые пока не являются частью продукта, см. [future-features.md](future-features.md).
