# Чек-лист публикации репозитория

Этот документ описывает настройки GitHub, которые не могут храниться в Git. Выполните их владельцу репозитория после слияния релизного pull request и до публичного анонса.

## Перед публикацией

1. Убедитесь, что в ветке `main` находится версия из `cmake/IBStartVersion.cmake`, а обязательная проверка `build` прошла успешно.
2. Проверьте автоматический выпуск тега `v<версия>` по [процессу выпуска](release-process.md): в GitHub Release должны появиться `IBStart.exe`, `IBStart-<версия>-portable-x64.zip`, `IBStart.version` и `checksums.txt`.
3. Проверьте, что в EXE и portable-архив не попали локальные списки баз, логи, пароли, токены или другие персональные данные; внутри portable ZIP должен быть пустой `IBStart.portable`.
4. Проверьте ссылки из `README.md`, `CONTRIBUTING.md`, `SECURITY.md` и шаблонов задач после открытия репозитория без авторизации.

## Настройки GitHub

1. Переведите репозиторий в публичный режим в настройках репозитория.
2. Включите раздел **Issues**. После слияния шаблоны из `.github/ISSUE_TEMPLATE` будут доступны в форме создания задачи.
3. Включите приватное сообщение об уязвимостях (**Private vulnerability reporting**). Политика раскрытия находится в [SECURITY.md](../SECURITY.md).
4. Включите Dependabot alerts, Dependabot security updates, secret scanning и push protection, если эти возможности доступны для репозитория.
5. Создайте правило защиты `main`: изменения только через pull request, обязательная успешная проверка `build`, запрет принудительной отправки и удаления ветки. Требование одобрения включайте в соответствии с составом команды.
6. Для GitHub Actions разрешите `GITHUB_TOKEN` создавать содержимое репозитория, необходимое для публикации release workflow. Это требуется только для автоматизированного выпуска релиза.

## После публикации

1. Откройте форму создания задачи и убедитесь, что доступны формы ошибки, предложения функции и вопроса.
2. Проверьте ссылку из формы ошибки на [политику безопасности](../SECURITY.md).
3. Проверьте кнопку ручной проверки обновлений в установленной версии: она должна получать `IBStart.version` последнего стабильного релиза и открывать его страницу только при наличии более новой версии.
