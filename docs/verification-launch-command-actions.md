# Добавление команд без аргументов

Дата: 2026-10-20. Ветка: `feat/launch-parameters-builder`.

## Причина и исправление

У части команд с синтаксисом, состоящим только из имени, в каталоге оставался
справочный тип. Форма отключала добавление, несмотря на отсутствие аргументов.
Исправление выбирает редактор по синтаксису точного профиля: такая команда
получает действие добавления и последующего удаления, поле значения скрыто.
Процессные режимы и справочные разделы остаются отдельными сущностями.

Сохраняются явно заданные редакторы значений. Например, краткий заголовок
`/AccessToken` не отменяет необходимость передачи токена, указанную в пояснении.
Старые формы `/AppAutoCheckVersion` и `/DisableLocalSpeechToText` без знака
учитываются отдельно от форм со знаком; неверный знак в старом профиле
по-прежнему диагностируется.

Кнопка «Добавить команду в строку» позволяет вставить только имя команды,
включая команды с необязательными опциями. Повторная вставка не дублирует
команду и не стирает её существующие опции. Для команд с обязательными
значениями это промежуточный черновик: до заполнения значений «Применить»
остаётся недоступной. Вставка учитывает версию и контекст запуска.

## Охват

Исправлены 22 справочных пункта хотя бы в одном из 24 профилей:

| Группа | Команды |
| --- | --- |
| Общие | `/AppAutoCheckMode`, `/AppCaptionFromInfobaseList`, `/ClearCache`, `/HttpsForceSSLv3`, `/LogUI`, `DisplayPerformance`, `UsePrivilegedMode` |
| Конфигуратор | `/IBRestoreIntegrity`, `/ResetMasterNode`, `/RunEnterprise`, `/Visible` |
| Хранилище | `/ConfigurationRepositoryClearCache`, `/ConfigurationRepositoryClearLocalCache` |
| Агент и OLE | `/AgentMode`, `/AgentSSHHostKeyAuto`, `/RegServer`, `/UnregServer` |
| Мобильные команды | `/MAUpdatePublication`, `/MobileAppUpdatePublication`, `/MobileClientDigiSign` |
| Тестовый профиль 8.5.4 | `/ManageLicenses`, `/ManageServers` |

Некоторые пункты имеют опции в поздних профилях. Например, `/RegServer`
распознаётся простым флагом в 8.3.6–8.3.8, а в последующих профилях сохраняет
редакторы областей регистрации. Новая кнопка позволяет добавить его без опций
и в этих профилях.

`/DisplayAllFunctions` уже имела тип флага: её недоступность в новом профиле
связана с матрицей версий. Она описана для 8.3.12–8.3.16; начиная с профиля
8.3.17 предусмотрена `/TechnicalSpecialistMode`. Историческая команда не
подменяется автоматически. [Матрица и официальные ссылки](launch-parameter-versions.md).

Две команды без начального `/` распознаются только в однозначном положении.
Совпадающее с именем команды значение `/C` не удаляется как команда; при
сборке такого значения добавляются кавычки. Неизвестные составные аргументы
сохраняются для ручной правки.

## Проверки

- Ядро обходит все профили и команды: распознавание флагов, добавление,
  отсутствие дубликатов, удаление, сохранение соседних фрагментов и версии.
- Отдельно проверяется вставка имени всех документированных CLI-команд,
  незавершённое обязательное значение, режим запуска и запрет подключения
  при вызове из дополнительных параметров базы.
- В настоящей Win32-форме проверены 22 исправленных пункта и историческая
  `/DisplayAllFunctions`: 23 команды в 334 сочетаниях команды и профиля.
  При первом появлении каждой команды проверяется добавление и удаление.
- Проверены новая кнопка для `/RegServer`, отсутствие дубликата, заполнение
  обязательного email после вставки и запрет вставки режимов и разделов.
- Предыдущая проверка 26 команд с основными аргументами продолжает проходить
  для 373 сочетаний с профилями.
- Release MSVC `/W4 /WX`: PASS; CTest: 5/5 PASS; Python: 44/44 PASS;
  строгая сборка документации и проверка ссылок: PASS.

Просмотрены снимки форм с добавленными `/ClearCache` и `/RegServer`: видны
команда в итоговой строке, состояние новой кнопки и действия с параметрами.

Проверка конструктора не запускает команды платформы, регистрацию OLE,
очистку кеша или операции с пользовательскими базами.
