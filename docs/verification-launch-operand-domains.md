# Проверка значений команд и вложенных опций

Дата: 2026-10-20.

Ветка: `feat/launch-parameters-builder`.

После этой проверки пользователь выбрал одиночный список для
`/ConfigurationRepositoryAddUser -Rights`. Итоговое поведение и последующая
смысловая сверка описаны в [новом протоколе](verification-launch-semantic-audit.md);
упоминание свободного ввода прав ниже фиксирует предыдущее состояние.

## Область сверки

Официальные источники указаны в [реестре документации](1c-reference-versions.md).

Проверялись правила обозначений из начала приложения, синтаксис всех команд
каталога и принадлежность перечислений из последующих пояснений. Отдельно
сопоставлены перечни значений с минусом, альтернативы в заголовках, условия
применения поля, содержимое файлов и параметры со списком через запятую.
Ревизия продолжает предыдущую [сверку описаний](verification-launch-help-its.md),
а не заменяет её доказательством исполнения команд в клиенте 1С.

После генерации получены 252 версионных варианта синтаксиса, 431 вариант
вложенных опций, 82 записи значений, 33 правила присутствия и 30 пар
взаимоисключающих опций. Эти числа относятся к объединённой грамматике
24 профилей и не означают число полей одной формы.

## Исправления

| Случай | Результат |
| --- | --- |
| `/debug [<режим>] [-attach]` | Одно необязательное поле режима с выбором `-tcp`/`-http`, отдельный необязательный флаг `-attach`. Варианты транспорта исключены из перечня независимых опций. |
| Проверка `/debug` | Команда без режима допустима. Два явных транспорта и сочетание `-tcp -attach` диагностируются. Пропуск режима не превращается в обязательный HTTP: фактический транспорт клиента конструктор не определяет. |
| `/CompareCfg` | Оба типа источника, правило сопоставления, тип и формат отчёта получают выбор по версии. Поля имён остаются свободными: названия типов в описании `-FirstName` являются условиями применения. |
| Форматы файлов | `Plain`/`Hierarchical` выбираются у опций, где они определены в профиле. У отчёта хранилища поддержан перечень `txt`/`mxl` из заголовка. Исчезнувший в 8.5.4 `-Format` не заимствуется из 8.5.1. |
| `/SignCfg` | Используются версионные домены исторической `-Type`, современной `-ConfigurationType` и появившейся в 8.5.1 `-SignType`. Имя расширения, путь и версия остаются строками. |
| Режимы обновления | Знаки `+`/`-` у вложенных режимов выбираются из списка. Необязательное значение `-Dynamic` допускает отсутствие знака; сериализация сохраняет слитную форму. |
| Команды стартера | `/AppAutoCheckVersion` и `/AppAutoInstallLastVersion` редактируют знак режима с присоединением к команде. У первой сохранена документированная возможность пропустить знак; в профилях 8.3.6/8.3.7, где знак ещё не описан, она редактируется как флаг. |
| Сложные значения | Перечень таблиц `/IBCheckAndRepair`, имена, пути и описания содержимого файлов не превращаются в выбор одного литерала. Перечень прав `-Rights` остаётся в справке, свободный ввод не ограничивается новой трактовкой сочетаний. |

Порядок значений в генерируемом домене сохраняет порядок их первого
документированного перечисления. Все варианты фильтруются по точному семейству
выбранной версии. Профили 8.5.2/8.5.3 отсутствуют; неизвестное семейство не
наследует домен из последней известной версии.

## Сохранность строки

Изменение транспорта заменяет только его значение. Удаление режима или
`-attach` сохраняет остальные элементы, соседние команды и неизвестный текст.
Повторные транспорты не перезаписываются через поля формы. Если совпавший
с `-http`/`-tcp` токен может быть значением неизвестной опции, структурированное
изменение режима также отклоняется, чтобы не изменить чужое значение.
Исходную строку можно исправить вручную.

## Проверки

- Синтетические Python-тесты извлечения: 36 проверок. Проверяются различие
  основного значения и опции, граница перечисления, альтернативы в заголовке,
  условия применения, содержимое файлов, необязательность и формы разделителей.
- Native unit: чтение, замена и удаление транспорта, конфликт HTTP/TCP,
  сохранение неизвестных фрагментов, запрет перезаписи неоднозначного ввода;
  проход по всем 24 профилям и редактируемым вложенным доменам.
- Реальные Win32-формы: два поля `/debug`, выбор HTTP, добавление `-attach`,
  смена на TCP с диагностикой, удаление флага и режима, ручное введение двух
  транспортов, свободное имя конфигурации, выбор знаков команд стартера,
  выбор формата частичной загрузки. Тесты выполняются на отдельном рабочем
  столе, без изменения пользовательских каталогов и запуска клиента.
- Сборка `msvc-x64-release`, CTest, проверка воспроизводимости грамматики,
  матрицы версий и версий документации; строгая сборка сайта документации.

Финальный полный прогон CTest: 5/5 успешно. В одном промежуточном прогоне
общие тесты записи `ibases.v8i` завершились отказом доступа при атомарной
замене файла, до проверки конструктора. Повторный полный прогон прошёл;
причина разового отказа не установлена. Код хранения файлов в этой доработке
не изменялся.

Снимки тестовой формы хранятся локально в
`out/ui-parameter-builder/operand-domains-2026-10-20/` и не входят в поставку.
Изображение `debug-mode.png` показывает поле режима, а `debug-http-attach.png`
— итоговую строку с HTTP и автоматическим подключением.

Выполнение отладки, обновления конфигурации, установки платформы и других
операций в установленной 1С в этой проверке не проводилось. Подтверждены
сверка модели с официальной документацией, работа редактора и проверки строки.
